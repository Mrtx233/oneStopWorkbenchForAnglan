# 商品颜色识别与复核

使用 Python 3.10+，安装 Pillow（仓库根目录的 `requirements.txt` 已包含）。以下命令从仓库根目录运行；`python` 应是已安装 Pillow 的可用解释器。

```powershell
python -m pip install "Pillow>=9.1"
python "Utils/Product color recognition/download_images.py" "D:/data/products.json"
python "Utils/Product color recognition/color_matcher.py" "D:/data/products.json"
```

也可以不带参数启动两个入口，按提示粘贴路径；支持资源管理器复制的带引号路径。下载器不再假定脚本旁存在某个特定网站的 JSON。

- 图片默认保存在 JSON 旁的 `images/<md5>/000.jpg`、`001.png` 等文件中，编号始终对应**原始 JSON 的 images 索引**。两个入口都接受第二个位置参数指定图片根目录。
- 下载器依据 `options` 中实际的颜色选项数量判断单色/多色，兼容 `Color`、`Colour`、`颜色` 等维度名，不依赖 `option_counts`。单色空链接会补为第一张图片 URL，并以原子替换方式写回输入 JSON；已有链接保持原样。
- 已开始复核或需要保持原始 JSON 不变时，下载器加 `--no-fill-single`。默认仍补单色链接，写回前会提示原文件变化将导致已有 `source_sha256` 校验不匹配。
- 多色商品要求有效且不冲突的 `md5`。发现无效数据会在改写输入 JSON 前退出。
- 仅完整可读且编号唯一的图片可跳过下载。失败结果记录在 `failed.txt`；重跑会更新失败列表，`manifest.csv` 同时包含已验证的缓存图片和本次成功下载的图片。
- 识别平台使用本地颜色规则，不调用远程 AI 服务。自动成功结果直接进入输出 JSON，仍建议人工确认；未知颜色和不确定结果留待人工处理。
- 平台默认另存 `<原文件名>_manual_labeled.json` 和对应的 `_progress.json`。续标时继续打开**原始输入 JSON**，并保留进度文件；不要用已删除部分 images 的结果文件替代原始输入。

## 复核界面

界面保存在 `ui/index.html`，由 Python 入口直接读取，无需 Node、Vue 构建或联网加载资源。移动或打包工具时请保留整个目录（包括 `ui`）。更新界面后，重启平台并刷新浏览器即可生效。

保留深色黑金三栏布局：左侧筛选商品，中间查看编号拼图，右侧选择颜色并确认或调整。金色用于当前选择，蓝框表示自动识别，绿框表示人工确认，金色虚框表示候选。窄屏按顺序排列各区域；图片区可横向滚动，避免将五列拼图缩成难以辨认的缩略图。所有修改仍自动保存，也可点击“保存 JSON”。

颜色卡片、图片标记和选色提示附带常见英文颜色的中文译名，例如 `Beige → 米色`、`Sage Green → 鼠尾草绿`。翻译离线完成，支持常见别名、组合色及条纹等修饰；未收录名称保留原文，已有中文不重复显示。译名仅供界面对照，不会修改 JSON 中的原始颜色键名或改变识别规则。

### 识别与高效复核

识别默认只依赖标准库和 Pillow。四边 Lab 色块模型和连通背景剔除适应轻微背景渐变；全前景软权重替代固定中心裁剪。存在足够非肤色主体时才抑制头部及肤色，避免把整件米杏色衣物当成皮肤。纯白、纯黑空图和疑似高对比尺码表不能自动成功；主体占比及边缘留白用于优先推荐全貌主图。

颜色评分使用纯 Python CIEDE2000，并提供有限的亮度及背景光偏色宽容。全局分配以原始 URL 为资源，重复 URL 不会被自动分配给多个颜色。未知色和图案色单独待复核；其他纯色按更严格阈值独立识别。分数是启发式指标，不代表正确率；近似中性色、图案和复杂场景仍需人工复核。

- 点击拼图上的“放大”、右键或 Shift + 点击，查看本地原图；未选颜色时直接点击图片也能预览。
- 识别未成功的颜色卡展示最多三个候选，包括原始 CIEDE2000 色差和目标占比，可直接采用，或先看大图再采用。经过光照宽容的色差用于判定，原始色差仍保留供核对。
- 图案或未知色优先推荐尚未占用的主图；因缺乏单色参考，只显示图号与占比，不虚构色差值。
- 进度区可“停止识别”。已完成商品保留；当前图片分析结束后退出，未完成商品可重新识别。停止收敛期间不能启动第二个任务。
- 快捷键：← / → 切换商品，N 跳到下个待复核商品，Enter 确认当前商品待确认结果，Esc 关闭预览。输入框、选择框和可编辑区域聚焦时不触发商品操作快捷键。

人工标注、人工确认、人工清除和原有链接均受保护。更换或清除原 Color 链接后，只存在于 Color 的旧图会退回 images。输入中重复的图片条目保留数量，每次分配仅消耗一条；原 Color 与 images 中重叠的链接按同一图片引用处理。其他商品字段保持原样。

进度仍为 version 2，兼容没有 candidates 的旧进度以及没有 version/origins 的纯手工进度。source_sha256 继续校验原始输入，新保存的进度还记录 output_sha256，防止输出 JSON 与侧车混用。保存前若原始输入已被外部修改会拒绝写入。两个文件分别原子替换；若进程在两次替换之间中断造成配套校验失败，请恢复匹配的输出和进度备份，或通过 --output 使用新文件。

### 离线回归测试

```powershell
python -m unittest discover -s "Utils/Product color recognition" -p "test_color_tools.py" -v
```

测试使用临时商品、合成图片和本地 HTTP 服务，不下载真实商品，不修改业务数据。覆盖色差参考值、全局分配与穷举比较、背景/肤色/无效图、进度兼容、守恒、人工与自动并发、停止和路径校验。Node 可用时额外检查前端 JavaScript 语法；Windows 无符号链接创建权限时跳过真实符号链接用例，同时始终执行解析后路径逃逸测试。
